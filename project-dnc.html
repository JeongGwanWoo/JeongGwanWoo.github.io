AI 기반 개인화 혈당 예측·식단 코칭 헬스케어 서비스

실시간 건강 데이터와 AI 분석 결과를 사용자별 식단 리포트 흐름으로 연결한 프로젝트입니다.

✔️ 기술 스택

JavaSpring BootJPAMySQLRedisFastAPIGemini APIDocker

✔️ 구현 사항

  • 외부 서비스 연동이 끊기지 않도록 만료되는 접근 토큰을 갱신하는 흐름을 구성했습니다.
  • 사용자의 센서 데이터를 주기적으로 받아와 식단 기록과 리포트에서 쓸 수 있는 데이터 흐름으로 연결했습니다.
  • 사용자마다 데이터를 따로 임시 저장해, 서로의 데이터가 섞이지 않도록 분리했습니다.
  • 이미 저장된 외부 데이터가 다시 들어와도 중복 저장되지 않도록 사용자와 기록 ID 기준을 확인했습니다.
  • AI 서버가 돌려준 분석 결과를 서비스의 식단·리포트 데이터로 사용할 수 있게 매핑했습니다.
  • 수집 데이터와 AI 요약 결과가 사용자가 보는 리포트로 이어지도록 연결 흐름을 정리했습니다.

✔️ 담당 역할

  • 토큰 갱신, 실시간 데이터 수집, 사용자별 임시 저장 흐름에 참여했습니다.
  • 중복 데이터 저장을 막기 위한 사용자와 기록 ID 기준 확인 흐름을 구성했습니다.
  • AI 분석 결과와 요약 내용을 리포트 흐름에 매핑했습니다.

✔️ 기술 선정 이유

  • Redis는 사용자별 실시간 데이터를 분리해 임시 저장하기 위해 사용했습니다.
  • FastAPI는 AI 분석 서버와 Spring Boot 서비스의 역할을 분리하기 위해 사용했습니다.
  • Gemini API는 리포트 요약처럼 사용자가 이해하기 쉬운 문장을 생성하기 위해 연동했습니다.

✔️ 프로젝트 성과

  • 외부 API, 임시 저장소, AI 서버, 리포트가 이어지는 전체 연동 흐름을 경험했습니다.
  • 사용자별 데이터 격리와 중복 방지가 외부 데이터 연동에서 중요하다는 점을 배웠습니다.
  • AI 기능은 정확도 주장보다 실패 처리와 결과 매핑 기준이 중요하다는 점을 확인했습니다.

✔️ 프로젝트 리뷰

  • 지금이라면 외부 API 실패, Redis 장애, AI 서버 실패에 대한 fallback과 모니터링 지표를 추가하겠습니다.
  • 건강 정보처럼 민감해 보이는 데이터는 공개 화면에서 더 강하게 익명화하고 표현 범위를 제한하겠습니다.
