DNC 당낭콩

AI 기반 개인화 혈당 예측·식단 코칭 헬스케어 서비스

CGM 데이터 수집과 식단 이미지 분석 결과를 개인화 식단 추천 및 Daily Report 흐름으로 연결한 서비스입니다.

✔️ 프로젝트 정보 및 구성

  • 2026.01 ~ 2026.02 · 약 5주 · 6인 · Mobile
  • GitHub Repository
  • 백엔드: Java 17, Spring Boot 3.5, Spring Data JPA
  • AI: FastAPI, YOLOv8
  • 모바일: React Native, Expo, TypeScript
  • 데이터·외부 연동: MySQL, Redis, Dexcom OAuth, FCM, AWS S3
  • 운영: Docker, NGINX, Jenkins

✔️ 담당 역할

  • Dexcom OAuth 연동과 CGM 데이터 수집·조회 흐름을 구현했습니다.
  • 식단 이미지 분석 요청과 AI 분석 결과 저장·처리를 구현했습니다.
  • 식단 추천과 Daily Report 생성·조회 흐름을 구현했습니다.

✔️ 구현 사항

  • Dexcom OAuth를 통해 CGM 데이터를 수집·조회하고, 사용자별 혈당 데이터를 서비스 흐름에 연결했습니다.
  • 식단 이미지를 S3 Presigned URL로 업로드한 뒤 FastAPI AI 서버에 분석을 요청하고 결과를 저장했습니다.
  • 분석 결과를 바탕으로 식단 추천을 생성하고, 최신 추천과 이전 추천을 조회할 수 있도록 구성했습니다.
  • 혈당과 식단 정보를 Daily Report로 정리하고, 사용자별 일일 리포트를 생성·조회하는 흐름을 구현했습니다.

✔️ 문제 해결

  • 문제Dexcom Sandbox 환경에서 deviceId 중복으로 다른 사용자의 CGM 데이터가 섞일 수 있었습니다.
  • 원인외부 deviceId만으로는 서비스 내부 사용자를 구분하기 어려웠습니다.
  • 해결사용자 정보를 기준으로 CGM 데이터와 조회 범위를 분리하고, FastAPI endpoint·응답 DTO와 Controller 파라미터를 명시적으로 맞췄습니다.
  • 결과사용자별 조회 경계를 명확히 하고, AI 연동·API 바인딩 오류 가능성을 줄였습니다.

✔️ 프로젝트 성과

  • 외부 CGM 데이터와 식단 분석 결과를 사용자별 리포트 흐름으로 연결했습니다.
  • AI 서버 endpoint와 응답 DTO의 계약을 정리해 연동 오류 가능성을 줄였습니다.
  • Controller 파라미터 이름을 명시해 일부 API의 바인딩 오류와 500 응답 가능성을 줄였습니다.

✔️ 프로젝트 리뷰

  • 지금이라면 외부 API, Redis, AI 서버 실패에 대한 fallback과 모니터링 지표를 더 보강하겠습니다.
  • 건강 데이터는 사용자별 조회 경계와 공개 화면의 표현 범위를 더 엄격하게 관리하겠습니다.
