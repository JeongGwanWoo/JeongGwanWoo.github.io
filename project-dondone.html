외국인 근로자를 위한 근무 기록 기반 급여 지갑

외국인 근로자의 근무 기록을 급여 확인·미리받기 흐름과 연결한 급여 지갑 서비스입니다.

✔️ 프로젝트 정보

  • 2026.02 ~ 2026.04 · 약 6주 · 5인 프로젝트
  • GitHub Repository

✔️ 구현 사항

  • 근무자의 출퇴근 기록을 급여 확인과 미리받기 흐름에서 재사용하는 기준 데이터로 정리했습니다.
  • WorkProof 출퇴근 기록과 근무 정정 요청 흐름을 구현했습니다.
  • 근무 정정 요청에 대한 고용주 승인·반려 흐름과 근무 기록 확정 처리를 구성했습니다.
  • 회사 등록 코드 기반 근로자 등록과 관리자·고용주용 승인 상태 조회 API를 구현했습니다.
  • GPS 위치 검증과 예외 상황의 검토 상태 처리 흐름을 구성했습니다.
  • 급여 확인 시점의 근무 증빙을 고정해 문서와 클레임 흐름에서도 같은 기준을 재사용할 수 있게 했습니다.

✔️ 문제 해결

  • 문제출퇴근 기록이 급여 확인, 문서, 클레임에서 각각 다르게 쓰이면 기준 데이터가 흔들릴 수 있었습니다.
  • 선택지기능마다 별도 데이터를 둘지, WorkProof 기록을 공통 증빙 기준으로 둘지 비교했습니다.
  • 해결출퇴근 기록을 기준 데이터로 정리하고, 급여 확인 snapshot과 문서·클레임 흐름에 연결했습니다.
  • 배운 점돈과 문서가 연결되는 기능에서는 데이터 기준이 흔들리지 않는 구조가 중요하다는 점을 배웠습니다.

✔️ 담당 역할

  • Spring Boot 기반 백엔드 API 구현에 참여했습니다.
  • 고용주·근로자·관리자 흐름 중 일부 기능을 구현했습니다.
  • WorkProof 출퇴근, 위치 검증, 검토 상태 흐름을 구현했습니다.

✔️ 기술 스택

Java 17Spring Boot 3.2Spring Data JPAReactViteAndroid KotlinPostgreSQLRedisSolidityFoundryWeb3jDockerNGINXJenkins

✔️ 기술 선정 이유

  • Spring Boot와 JPA는 근무 기록, 급여, 문서 도메인을 명확히 나누기 위해 사용했습니다.
  • PostgreSQL은 근무 기록과 검토 상태처럼 관계가 분명한 데이터를 저장했습니다.
  • Solidity, Foundry, Web3j를 미리받기 관련 블록체인 구성에 사용했습니다.

✔️ 프로젝트 성과

  • 하나의 출퇴근 기록을 여러 업무 흐름에서 재사용하는 데이터 기준을 경험했습니다.
  • 예외 상황을 실패로 끝내기보다 검토 가능한 상태로 남기는 설계의 필요성을 배웠습니다.
  • 문서와 클레임 기능에서는 기준 데이터가 흔들리지 않는 것이 중요하다는 점을 확인했습니다.

✔️ 프로젝트 리뷰

  • 지금이라면 WorkProof → Wage → Documents/Claim 흐름을 기능 단위 테스트로 더 촘촘히 검증하겠습니다.
  • 선지급 요청처럼 중복 요청 위험이 있는 기능은 Idempotency-Key 정책을 더 명확히 문서화하겠습니다.
