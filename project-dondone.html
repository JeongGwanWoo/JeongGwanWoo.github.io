구현 내용 정리

✔️ 기술 스택

JavaSpring BootJPAMySQLRedisDockerJenkinsNGINX

✔️ 구현 사항

  • 근무자의 출근·퇴근 기록을 이후 급여 확인과 문서 흐름에서 다시 쓸 수 있는 기준 데이터로 정리했습니다.
  • GPS 위치가 근무지 기준과 맞는지 확인하고, 예외 상황을 바로 버리지 않도록 흐름을 나눴습니다.
  • 위치 기준을 벗어난 퇴근 기록을 실패로 끝내지 않고 관리자가 확인할 수 있는 상태로 남겼습니다.
  • 급여 확인 시점의 근무 증빙을 고정해, 나중에 문서와 클레임에서 같은 기준을 재사용할 수 있게 했습니다.
  • 출퇴근 기록을 문서 생성과 클레임 준비 흐름에 연결해, 기능마다 다른 기준을 쓰지 않도록 했습니다.
  • 사업장 등록 검토와 선지급 승인처럼 관리자가 확인해야 하는 요청 흐름 일부를 구성했습니다.

✔️ 담당 역할

  • WorkProof 출퇴근, 위치 검증, 검토 상태 흐름 구현에 참여했습니다.
  • 급여 확인 기록과 문서/클레임 증빙 연결 흐름을 구성했습니다.
  • 사업장 검토와 관리자 승인처럼 운영자가 확인해야 하는 일부 흐름에 참여했습니다.

✔️ 기술 선정 이유

  • Spring Boot와 JPA는 근무 기록, 급여, 문서 도메인을 명확히 나누기 위해 사용했습니다.
  • MySQL은 근무 기록과 검토 상태처럼 관계가 분명한 데이터를 저장하기 위해 사용했습니다.
  • Redis는 인증이나 반복 조회가 필요한 임시 데이터를 빠르게 다루기 위해 사용했습니다.

✔️ 프로젝트 성과

  • 하나의 출퇴근 기록을 여러 업무 흐름에서 재사용하는 데이터 기준을 경험했습니다.
  • 예외 상황을 실패로 끝내기보다 검토 가능한 상태로 남기는 설계의 필요성을 배웠습니다.
  • 문서와 클레임 기능에서는 기준 데이터가 흔들리지 않는 것이 중요하다는 점을 확인했습니다.

✔️ 프로젝트 리뷰

  • 지금이라면 WorkProof → Wage → Documents/Claim 흐름을 기능 단위 테스트로 더 촘촘히 검증하겠습니다.
  • 선지급 요청처럼 중복 요청 위험이 있는 기능은 Idempotency-Key 정책을 더 명확히 문서화하겠습니다.
