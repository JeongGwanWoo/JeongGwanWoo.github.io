MyTripQuest

GPS와 AI 사진 인증을 활용한 위치 기반 여행 퀘스트 플랫폼

관광지 정보, 위치 도착 확인, 사진 인증을 퀘스트 완료와 보상 흐름으로 연결한 여행 서비스입니다.

✔️ 구현 사항

  • 공공 관광지 정보를 받아와 퀘스트 장소와 화면에서 사용할 수 있는 데이터로 연결했습니다.
  • 사용자의 현재 위치가 관광지 근처인지 확인해 퀘스트 완료 조건의 첫 단계를 판단했습니다.
  • 방문 인증 사진을 AI 판정 흐름과 연결해 위치 확인 이후의 추가 인증 단계로 분리했습니다.
  • 도착 확인과 사진 인증 결과에 따라 퀘스트 진행 상태가 바뀌도록 흐름을 나눴습니다.
  • 퀘스트 완료 이후 보상, 아바타, 랭킹으로 이어지는 사용자 보상 흐름을 구성했습니다.
  • 사용자 로그인 이후 토큰 기반으로 접근 권한을 확인하는 인증 흐름을 구성했습니다.

✔️ 문제 해결

  • 문제퀘스트 완료를 단순 버튼 클릭이 아니라 실제 방문 여부에 가깝게 판단해야 했습니다.
  • 선택지GPS만 사용하는 방식, 사진만 사용하는 방식, GPS 확인 후 AI 사진 인증을 추가하는 방식을 비교했습니다.
  • 해결위치 도착 확인과 사진 인증을 단계별 조건으로 나누고, 결과에 따라 퀘스트 상태가 변경되도록 구성했습니다.
  • 배운 점인증 기능은 조건을 한 번에 묶기보다 단계별로 나누는 것이 예외 처리와 설명에 유리하다는 점을 배웠습니다.

✔️ 담당 역할

  • 관광지 정보 연동과 위치 도착 확인 흐름 구현에 참여했습니다.
  • 사진 인증 결과를 퀘스트 상태 변경과 보상 처리 흐름으로 연결했습니다.
  • JWT/OAuth2 기반 로그인 이후 접근 권한 처리 흐름에 참여했습니다.

✔️ 기술 스택

JavaSpring BootJPAMySQLJWTOAuth2TourAPIDocker

✔️ 기술 선정 이유

  • TourAPI는 실제 관광지 데이터를 기반으로 여행 퀘스트를 만들기 위해 사용했습니다.
  • JWT와 OAuth2는 로그인 이후 사용자별 퀘스트 접근을 분리하기 위해 사용했습니다.
  • Spring Boot와 JPA는 장소, 퀘스트, 보상 도메인을 안정적으로 관리하기 위해 사용했습니다.

✔️ 프로젝트 성과

  • 위치 확인과 사진 인증을 한 덩어리로 보지 않고 단계별 조건으로 나누어 구현했습니다.
  • 관광지 데이터, 사용자 행동, 보상 흐름이 연결되는 서비스 구조를 경험했습니다.
  • 2인 프로젝트에서 역할을 나누고 서로의 구현 흐름을 맞추는 협업 경험을 얻었습니다.

✔️ 프로젝트 리뷰

  • 지금이라면 테스트 실행 환경을 분리하고 위치·사진 인증 실패 케이스를 더 많이 검증하겠습니다.
  • OAuth2 로그인 이후 토큰 전달 방식은 URL 전달보다 HttpOnly Cookie나 일회성 code 방식으로 개선하겠습니다.
